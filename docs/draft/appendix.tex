\subsection{Information versus architecture}
\label{sec:grid}

The test set fixes the prompt; the development set is where the prompt was
varied one decision at a time. Table~\ref{tab:grid} separates what the prompt
tells the 2024 pair from what the decomposition adds. Stating the conventions
to the end-to-end model is worth $+0.09$ (A$\rightarrow$B); two plan-free
repair rounds another $+0.07$; handing the composed plan to S2 as prose is
\emph{below} the end-to-end control (0.573) and level with it after repair
(0.645); resolving the plan into its rule gives 0.855 with nothing else
changed. At 7B nothing moves the cohort tiers above 0.45, and the conventions
cost the end-to-end 7B model accuracy (B $<$ A): a model that cannot compose
the plan cannot use the stipulations either.

\paragraph{Retrieval: attribution.} Every prediction records the report
identifiers it placed in each arm, so every wrongly included or dropped report
can be checked against the claim's rule in the database and named
(Table~\ref{tab:attribution}). The largest single cause in the end-to-end rows
had been invisible to every aggregate metric: the query defines the eligible
set as the supporting set, so $n = k$ and the claim is supported for free (87
of 258 records for B). Repair rounds remove failed statements and most $n = k$
queries; what remains for the end-to-end model is semantic --- co-existing

\paragraph{Conventions as information, one change at a time.} Three
prompt-level decisions were each made as a single controlled change on the
development subset, with everything else fixed. \emph{One missing
stipulation:} under an earlier conventions text the 32B planner composed every
association claim (C-V2) as one-arm co-occurrence --- 0 of 18 records ---
although the ``compare the rate with and without $A$'' situation was stated;
the three association wordings were never bridged to it, while ``occur
together'' matched the co-occurrence stipulation. Adding that bridge moved the
planner from 0.897 to 0.950, with 23 of 26 groups unchanged record for record
(C-V2 0.00 $\rightarrow$ 0.67; a co-occurrence bar group 0.00 $\rightarrow$
1.00). A model is not wrong about a situation it was never told exists.
\emph{Schema presentation:} showing the SQL model the \texttt{CREATE VIEW}
bodies of the helper views led it to copy the views' internal aliases into its
own queries (117 rejected statements of 466 in cell A); listing the views as
columns with their semantics in comments removed that error but left an
ambiguous unqualified identifier in self-joins (157 rejected); one sentence in
the row contract removed that too (34 rejected). Cell A went 0.297
$\rightarrow$ 0.378 $\rightarrow$ 0.502 and the SQL stage with the gold plan
0.810 $\rightarrow$ 0.830 $\rightarrow$ 0.900. None of these changed the data,
the models or the method; they are the cost of a prompt artefact that would
otherwise have read as a finding about the new claim families.

\section{Cost and latency}
\label{app:cost}

Table~\ref{tab:cost} gives, per test record, the wall time of the sequential
harness, the tokens exchanged and the dollar cost from the providers' own
usage counts at list price with prompt caching; local rows cost GPU time only.
The contract pipeline makes two calls per record where the end-to-end
baseline makes one, so it exchanges about twice the tokens, and the verifier
adds 10--20\% on top. A full ten-row frontier column on the test set cost
\$80 (Opus) and \$89 (GPT-5.6, which spends hidden reasoning tokens on the
test-stage judgment); a 31B open model answers a test claim in 14~seconds on
one workstation GPU and a 27B one in 10.
